## wxWidgets 图像渲染流程与高性能实践（Windows / Linux）

本文基于当前仓库中的 wxWidgets 源码（尤其是 `src/msw/*.cpp`、`src/gtk/*.cpp`、`src/generic/graphicc.cpp` 等），梳理在 Windows 与 Linux(GTK) 下图像渲染的实际调用链，并给出面向高性能渲染的推荐实现方式。

---

### 1. 核心概念与数据流

- `wxImage`
  - 纯内存图像，按行顺序存放 `RGB(+Alpha)` 数据，方便读写、缩放、像素操作。
  - 不依赖平台 GDI/GPU，对绘制效率不敏感，但**转换为可直接渲染的形式（`wxBitmap` / `wxGraphicsBitmap`）是有成本的**。

- `wxBitmap`
  - 设备相关（device-dependent）的图像对象，是大部分 DC/GC API 的输入类型。
  - 内部封装平台句柄：
    - Windows：`HBITMAP` + 可选 `HBITMAP` mask（`src/msw/bitmap.cpp` 系列）。
    - GTK3：`GdkPixbuf` + 可选 `cairo_surface_t` 缓存（例如 `wxBitmap::CairoCreate()` 使用，见 `src/gtk/bitmap.cpp`）。
  - 具备 `m_scaleFactor`，在高 DPI/缩放场景下自动调整绘制尺寸（`src/gtk/bitmap.cpp:1405-1413`）。

- `wxGraphicsBitmap`
  - 针对 `wxGraphicsContext` 的位图封装，直接面向底层渲染后端：
    - Windows GDI+：`wxGDIPlusBitmapData` 包装 `Gdiplus::Bitmap`（`src/msw/graphics.cpp:330-347, 1248-1412`）。
    - Direct2D：`wxD2DBitmapData` 包装 `ID2D1Bitmap`（`src/msw/graphicsd2d.cpp`）。
    - Cairo：`wxCairoBitmapData` 包装 `cairo_surface_t` + `cairo_pattern_t`（`src/generic/graphicc.cpp:380-415, 1601-1797`）。

- `wxDC` 系列（`wxPaintDC` / `wxClientDC` / `wxMemoryDC` / `wxScreenDC` 等）
  - 传统 2D 绘图接口，提供 `DrawBitmap()`、`Blit()` 等 API。
  - 在 GTK3/MSW 实现中，`wxDCImpl` 多数最终会委托给平台 GDI 或 `wxGraphicsContext` 进行实际绘制。

- `wxGraphicsContext` / `wxGraphicsRenderer`
  - 现代 2D 渲染 API，支持向量路径、抗锯齿、复杂 alpha 合成。
  - 底层由不同的 `wxGraphicsRenderer` 实现：
    - Windows：`wxGDIPlusRenderer`（默认）、`wxD2DRenderer`（可选）。
    - GTK / 其他：`wxCairoRenderer`（`src/generic/graphicc.cpp`）。

典型数据流（跨平台通用）：

1. 加载阶段：`wxImage` ← 从文件/内存/网络读取。
2. 准备阶段：`wxImage` 处理（缩放、裁剪、像素处理），然后转换为 `wxBitmap`。
3. 渲染准备：根据需要将 `wxBitmap` 转换为长期缓存的 `wxGraphicsBitmap`。
4. 绘制阶段：在 `wxDC` / `wxGCDC` / `wxGraphicsContext` 中调用 `DrawBitmap()` 或 `Blit()`，最终落到平台 GDI/Cairo/Direct2D。

**高性能关键点**：尽量让“昂贵步骤”（2→3）发生在初始化/缓存阶段，而不是每次 `OnPaint` 重复执行。

### 2. Windows 平台图像渲染流程

#### 2.1 传统 `wxDC` 路径（GDI）

以 `wxMSWDCImpl::DoDrawBitmap()` 为核心（`src/msw/dc.cpp:1152`）：

- 调用链（典型窗口绘制）：
  1. 用户代码：`wxPaintDC dc(this); dc.DrawBitmap(bmp, x, y, useMask);`
  2. `wxPaintDC` → `wxWindowDC` → `wxMSWDCImpl::DrawBitmap()`。
  3. 实际绘制逻辑位于 `wxMSWDCImpl::DoDrawBitmap()`（`src/msw/dc.cpp:1152`）。

- 主要逻辑（`src/msw/dc.cpp:1156-1192` 等）：
  - 计算位图宽高。
  - 如果位图含 alpha：
    - 如果同时存在 mask，需要将 mask 混入 alpha 通道（`curBmp.MSWBlendMaskWithAlpha()`），避免 `MaskBlt()` 对 32bpp RGBA 的兼容性问题（`src/msw/dc.cpp:1171-1181`）。
    - 将位图选入临时 `MemoryHDC`，调用 `AlphaBlt()`/`AlphaBlend()` 进行带 alpha 的 `BitBlt`（`src/msw/dc.cpp:1188-1192`）。
  - 如果无 alpha：
    - 按 `useMask` 决定是否调用 `MaskBlt()` 或直接 `BitBlt()`，并结合调色板（`wxUSE_PALETTE` 相关代码段）。

特点：

- 完全 GDI 路径，通常 CPU 渲染，无 GPU 加速。
- 对简单 UI 图标、小图非常高效，对大量全屏 alpha 合成、频繁缩放场景性能有限。

适用场景：

- 传统 GDI 风格界面，小量位图绘制。
- 打印 / 兼容性要求较高的环境。

#### 2.2 `wxGraphicsContext` + GDI+ 路径（默认高层渲染）

核心代码：

- 默认图形渲染器：
  - `wxGraphicsRenderer::GetDefaultRenderer()` 在 MSW 下返回 GDI+ 渲染器（`src/msw/graphics.cpp:2663-2665`）：
    ```cpp
    wxGraphicsRenderer* wxGraphicsRenderer::GetDefaultRenderer()
    {
        return wxGraphicsRenderer::GetGDIPlusRenderer();
    }
    ```

- GDI+ 位图封装：
  - `wxGDIPlusBitmapData`（`src/msw/graphics.cpp:330-348`）持有 `Gdiplus::Bitmap*`：
    - 从 `wxBitmap` 构造时，针对 mask 和 alpha 做转换，生成 `PixelFormat32bppPARGB` 格式（`src/msw/graphics.cpp:1248-1293`）。
    - 从 `wxImage` 构造时，逐像素写入 `b,g,r,a`，并根据 mask 决定透明区域（`src/msw/graphics.cpp:1352-1412`）。

- GDI+ 绘制实现：
  - `wxGDIPlusContext::DrawBitmap(const wxGraphicsBitmap& bmp, ...)`（`src/msw/graphics.cpp:2299-2317`）：
    - 从 `wxGDIPlusBitmapData` 取出 `Bitmap*`。
    - 如果目标宽高与位图尺寸不同，构造 `Rect` 进行缩放绘制：
      ```cpp
      Rect drawRect((REAL)x, (REAL)y, (REAL)w, (REAL)h);
      m_context->SetPixelOffsetMode(PixelOffsetModeNone);
      m_context->DrawImage(image, drawRect, 0, 0, image->GetWidth(), image->GetHeight(), UnitPixel);
      m_context->SetPixelOffsetMode(PixelOffsetModeHalf);
      ```
    - 否则直接 `m_context->DrawImage(image,(REAL)x,(REAL)y,(REAL)w,(REAL)h);`

- 与 `wxGCDC` 的集成：
  - `wxGCDCImpl::DoDrawBitmap()`（`src/common/dcgraph.cpp:255-282`）：
    - 对非单色位图：复制一份以便根据 `useMask` 删除 mask，然后调用 `m_graphicContext->DrawBitmap(bmpCopy, x, y, w, h);`
  - 在 MSW 上，`wxGCDC` 的 `m_graphicContext` 默认就是 `wxGDIPlusContext`。

结果：

- 从用户视角：`wxGCDC` 或直接 `wxGraphicsContext` 的 `DrawBitmap()`。
- 实际路径：`wxGraphicsContext` → `wxGDIPlusContext` → GDI+ `Graphics::DrawImage()`。
- 相比纯 GDI：
  - 更好的 alpha 合成与插值控制。
  - 支持矢量路径、阴影、渐变等高级操作。

推荐：

- 需要**高质量缩放 + alpha 合成 + 控制插值质量**时，优先使用 `wxGCDC` / `wxGraphicsContext` 路径。

#### 2.3 `wxGraphicsContext` + Direct2D 路径（可选 GPU 加速）

Direct2D 支持由 `wxUSE_GRAPHICS_DIRECT2D` 控制（`include/wx/msw/setup.h:1538-1548`）：

- 渲染器获取：
  - `wxGraphicsRenderer::GetDirect2DRenderer()`（`src/msw/graphicsd2d.cpp:5143-5148`）：
    - 内部调用 `wxDirect2D::Initialize()`，并缓存 `gs_D2DRenderer`。

- D2D 绘制核心：
  - `wxD2DContext::DrawBitmap(const wxGraphicsBitmap& bmp, ...)`（`src/msw/graphicsd2d.cpp:4653-4668`）：
    - 将 `wxGraphicsBitmap` 转换为 `wxD2DBitmapData`，绑定到当前 `RenderTarget`。
    - 使用 `m_renderTargetHolder->DrawBitmap(...)`：
      ```cpp
      m_renderTargetHolder->DrawBitmap(
          bitmapData->GetD2DBitmap(),
          D2D1::RectF(0, 0, bmpSize.GetWidth(), bmpSize.GetHeight()),
          D2D1::RectF(x, y, x + w, y + h),
          GetInterpolationQuality(),
          GetCompositionMode());
      ```
  - 内部具体实现根据 RenderTarget 类型选择 `ID2D1RenderTarget::DrawBitmap()` 或 `ID2D1DeviceContext::DrawImage()`（`src/msw/graphicsd2d.cpp:3378-3388, 3555-3565`）。

- 选择 Direct2D 的方式（示意）：
  ```cpp
  wxGraphicsRenderer* renderer = wxGraphicsRenderer::GetDirect2DRenderer();
  if (!renderer)
      renderer = wxGraphicsRenderer::GetDefaultRenderer(); // 回退 GDI+

  wxGraphicsContext* gc = renderer->CreateContextFromNativeWindow(
      (void*)GetHWND(this)); // 或 CreateContext(wxWindowDC)
  ```

特点：

- GPU 加速的 2D 渲染，对大量位图缩放、旋转、混合场景更有优势。
- 支持丰富的采样 / 合成质量控制。

推荐：

- Windows 7+，需要高 FPS、大量 alpha 位图、复杂动画时，应优先尝试 Direct2D 后端。

##### 2.3.1 D3D11 设备上下文路径（Direct2D 1.1）

源码中还预留了基于 D3D11 的 Direct2D 1.1 渲染路径，对应 `ID2D1DeviceContext` + DXGI 交换链（目前由编译期宏控制，默认关闭）：

- 编译期开关：
  - `src/msw/graphicsd2d.cpp:15` 定义：
    ```cpp
    #define wxD2D_DEVICE_CONTEXT_SUPPORTED 0
    ```
  - 为 1 时，将启用 D3D11 设备上下文后端，并在 `wxDirect2D::LoadLibraries()` 中加载 `d3d11.dll`、导入 `D3D11CreateDevice`，同时将 Direct2D 版本标记为 1.1（`src/msw/graphicsd2d.cpp:160-181`）。

- D3D11 设备与 D2D 设备上下文创建：
  - 封装类：`wxD2DDeviceContextResourceHolder`（`src/msw/graphicsd2d.cpp:3545-3730`），继承自 `wxD2DRenderTargetResourceHolder`。
  - 在 `DoAcquireResource()` 中：
    1. 调用 `D3D11CreateDevice()` 创建 `ID3D11Device` 与 `ID3D11DeviceContext`：
       ```cpp
       UINT creationFlags = D3D11_CREATE_DEVICE_BGRA_SUPPORT;
       D3D_FEATURE_LEVEL featureLevels[] = { ... };
       hr = D3D11CreateDevice(
           nullptr, D3D_DRIVER_TYPE_HARDWARE, 0,
           creationFlags,
           featureLevels, ARRAYSIZE(featureLevels),
           D3D11_SDK_VERSION,
           &device, &m_featureLevel, &context);
       ```
    2. 通过 `device->QueryInterface(IID_IDXGIDevice, ...)` 获取 `IDXGIDevice1`。
    3. 使用 `ID2D1Factory1::CreateDevice()` 从 DXGI 设备创建 `ID2D1Device`，再调用 `CreateDeviceContext()` 得到 `ID2D1DeviceContext`，并作为 `m_nativeResource`。

- DXGI 交换链与渲染目标：
  - `AttachSurface()` 中（`src/msw/graphicsd2d.cpp:3639-3679`）：
    1. 填充 `DXGI_SWAP_CHAIN_DESC1`（两帧缓冲、`DXGI_FORMAT_B8G8R8A8_UNORM`、`DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL` 等）。
    2. 通过 `m_dxgiDevice->GetAdapter()` 获取 `IDXGIAdapter`，再 `GetParent(IID_PPV_ARGS(&dxgiFactory))` 获得 `IDXGIFactory2`。
    3. 调用 `CreateSwapChainForHwnd(m_dxgiDevice, m_hwnd, &swapChainDesc, ...)` 创建 `IDXGISwapChain1`。
    4. 通过 `IDXGISwapChain1::GetBuffer()` 获取 back buffer `ID3D11Texture2D`，再转换为 `IDXGISurface`，调用 `ID2D1DeviceContext::CreateBitmapFromDxgiSurface()` 创建 `ID2D1Bitmap1` 作为 D2D 的目标 bitmap，并 `m_context->SetTarget(m_targetBitmap)`。
    5. 调用 `m_dxgiDevice->SetMaximumFrameLatency(1)` 限制队列帧数，降低输入延迟。

- 位图绘制与显示：
  - `wxD2DDeviceContextResourceHolder::DrawBitmap()`（`src/msw/graphicsd2d.cpp:3555-3565`）：
    - 使用 `ID2D1DeviceContext::DrawImage()` 在 GPU 上进行采样/插值与合成：
      ```cpp
      D2D1_POINT_2F offset = D2D1::Point2(destRect.left, destRect.top);
      m_context->DrawImage(bitmap,
          offset,
          srcRect,
          wxD2DConvertInterpolationMode(interpolationQuality),
          wxD2DConvertCompositionMode(compositionMode));
      ```
  - `Flush()`（`src/msw/graphicsd2d.cpp:3568-3573`）：
    - 先调用 `m_nativeResource->Flush()` 提交 D2D 命令，然后通过 `m_swapChain->Present1(...)` 将图像显示到屏幕。
  - 析构函数中也会执行一次 `Present1()`，保证最后一帧刷新（`src/msw/graphicsd2d.cpp:3713-3717`）。

- 与窗口上下文的关系：
  - 在 `wxD2DContext(wxGraphicsRenderer*, ID2D1Factory*, HWND)` 构造函数中（`src/msw/graphicsd2d.cpp:4085-4095`）：
    - 当 `wxD2D_DEVICE_CONTEXT_SUPPORTED` 为 1：
      ```cpp
      m_renderTargetHolder(new wxD2DDeviceContextResourceHolder(direct2dFactory, hwnd))
      ```
    - 为 0 时退化为传统的 `ID2D1HwndRenderTarget` 路径：
      ```cpp
      m_renderTargetHolder(new wxD2DHwndRenderTargetResourceHolder(hwnd, direct2dFactory))
      ```

- 版本检测与应用侧感知：
  - `wxD2DRenderer::GetVersion()`（`src/msw/graphicsd2d.cpp` 尾部）会根据 `wxDirect2D::GetDirect2DVersion()` 返回：
    - `major=1, minor=0`：Direct2D 1.0（传统 HwndRenderTarget，间接依赖 D3D）。
    - `major=1, minor=1`：Direct2D 1.1（显式 D3D11 设备上下文 + DXGI 交换链）。
  - 应用侧可调用：
    ```cpp
    int major, minor, micro;
    auto* d2d = wxGraphicsRenderer::GetDirect2DRenderer();
    if (d2d)
        d2d->GetVersion(&major, &minor, &micro);
    ```
    在需要针对 D2D 1.1/D3D11 做优化时（例如更精细的插值模式、与其它 D3D 内容共享 DXGI 资源），可以据此做分支。

整体上，**D3D11 路径并不改变 wxWidgets 对外的 `wxGraphicsContext`/`wxGraphicsBitmap` API**，而是通过更底层的 D3D11 + DXGI + D2D1.1 组合，提供更稳定的高帧率与更好的多显示器/高 DPI 支持，对大量 GPU 加速图像渲染场景更友好。

#### 2.4 Windows 典型调用链对比

1. 传统 GDI：
   - `wxPaintDC` → `wxMSWDCImpl::DoDrawBitmap()` → `BitBlt/MaskBlt/AlphaBlend`。

2. 现代 2D（默认 GDI+）：
   - `wxAutoBufferedPaintDC` + `wxGCDC` → `wxGCDCImpl::DoDrawBitmap()` → `wxGDIPlusContext::DrawBitmap()` → GDI+。

3. 现代 2D（显式 Direct2D）：
   - 获取 `wxD2DRenderer` + 手动创建 `wxGraphicsContext` → `wxD2DContext::DrawBitmap()` → Direct2D GPU。

### 3. Linux (GTK3) 平台图像渲染流程

#### 3.1 GTK3 下的 `wxDC` + Cairo 路径

GTK3 使用 `wxGTKCairoDCImpl`（`src/gtk/dc.cpp`），它继承自 `wxGCDCImpl`，并强制使用 Cairo 作为后台实现。

- 典型 DC 实现：
  - `wxClientDCImpl` / `wxPaintDCImpl` / `wxScreenDCImpl` / `wxMemoryDCImpl` 等均继承 `wxGTKCairoDCImpl`（`src/gtk/dc.cpp:409-452, 458-504, 529-560, 580-604`）。
  - 构造函数中：
    - 从 `GtkWidget` / `GdkWindow` 获取原生 `cairo_t*`：
      - `wxGTKImpl::CairoContext` 封装了 `gdk_cairo_create(window)`（`include/wx/gtk/private/cairo.h`）。
      - 或由 `wxWindow::GTKPaintContext()` 提供（`wxPaintDCImpl`）。
      - 或通过 `wxBitmap::CairoCreate()` 从位图创建 Cairo 上下文（`wxMemoryDCImpl::Setup()`，`src/gtk/dc.cpp:588-604`）。
    - 调用 `wxGraphicsContext::CreateFromNative(cr)` 把 `cairo_t*` 关联到一个 `wxGraphicsContext`，之后通过 `SetGraphicsContext(gc)` 存入 `wxGTKCairoDCImpl`（`src/gtk/dc.cpp:430-452, 462-472, 593-604`）。

- 位图绘制核心：
  - `wxGTKCairoDCImpl::DoDrawBitmap()`（`src/gtk/dc.cpp:53-72`）：
    1. 从 `m_graphicContext` 提取原生 `cairo_t*`：
       ```cpp
       cairo_t* cr = nullptr;
       if (m_graphicContext)
           cr = static_cast<cairo_t*>(m_graphicContext->GetNativeContext());
       ```
    2. 如为 RTL 布局，反向缩放处理 x 坐标。
    3. 调用 `wxBitmap::Draw(cr, x, y, useMask, &fg, &bg)` 完成真正绘制。

  - `wxBitmap::Draw()` 实现在 `src/gtk/bitmap.cpp:1401-1434`：
    - 如 `m_scaleFactor != 1`，先对 Cairo 进行 `translate` + `scale`，保证逻辑尺寸与缩放一致。
    - 设置 source surface：
      ```cpp
      SetSourceSurface(cr, x, y, fg, bg);
      cairo_pattern_set_filter(cairo_get_source(cr), CAIRO_FILTER_NEAREST);
      ```
    - 如存在 mask，创建 mask surface 的 pattern，通过 `cairo_mask()` 应用；否则直接 `cairo_paint()`。

总结：

- GTK3 下即便用户只使用传统 `wxDC::DrawBitmap()`，最终也会走 `wxGraphicsContext` + Cairo 路径。
- 位图像素由 `GdkPixbuf` / `cairo_surface_t` 承载，绘制时通过 Cairo pattern 复制到窗口表面。

#### 3.2 直接使用 `wxGraphicsContext` + Cairo

当启用了 `wxUSE_CAIRO` 时，通用 Cairo 渲染器定义在 `src/generic/graphicc.cpp`：

- Cairo 渲染器：
  - `wxCairoRenderer` 实现 `wxGraphicsRenderer`（`src/generic/graphicc.cpp`，尾部）。
  - `wxGraphicsRenderer::GetCairoRenderer()` 返回单例 `gs_cairoGraphicsRenderer`，`GetDefaultRenderer()` 在非 MSW/OSX/Qt 平台上返回它（`src/generic/graphicc.cpp` 末尾）。

- 位图封装：
  - `wxCairoBitmapData`（`src/generic/graphicc.cpp:380-415, 1601-1797`）：
    - 从 `wxBitmap` 构造：
      - 根据位图 bpp 与 mask 情况，分配 `CAIRO_FORMAT_ARGB32` 或 `CAIRO_FORMAT_RGB24` 缓冲区。
      - 通过 `wxAlphaPixelData` 或 `wxNativePixelData` 遍历原始像素，将其拷贝并在有 alpha/mask 时做预乘（`Premultiply()`，`Unpremultiply()` 逻辑在文件顶部匿名命名空间内）。
      - 通过 `cairo_image_surface_create_for_data()` + `cairo_pattern_create_for_surface()` 创建 surface 与 pattern。
    - 从 `wxImage` 构造：
      - 类似逻辑，将 `wxImage` 中的 `RGB(+Alpha)` 转换为预乘 ARGB32（`src/generic/graphicc.cpp:1758-1797`）。

- 绘制实现：
  - `wxCairoContext::DrawBitmap(const wxBitmap& bmp, ...)`（`src/generic/graphicc.cpp:2896-2901`）：
    - 内部直接 `CreateBitmap(bmp)` 得到 `wxGraphicsBitmap`，再调用另一个重载。
  - `wxCairoContext::DrawBitmap(const wxGraphicsBitmap& bmp, ...)`（`src/generic/graphicc.cpp:2903-2926`）：
    - 从 `wxCairoBitmapData` 取得 `cairo_pattern_t*` 和原始尺寸。
    - 使用 `cairo_translate` + `cairo_scale` 进行缩放，再在 (0,0)~(w,h) 矩形内 `cairo_fill()`：
      ```cpp
      cairo_translate(m_context, x, y);
      cairo_scale(m_context, scaleX, scaleY);
      cairo_set_source(m_context, pattern);
      cairo_rectangle(m_context, 0, 0, size.GetWidth(), size.GetHeight());
      cairo_fill(m_context);
      ```

特点：

- 所有缩放都通过 Cairo 矩阵完成，利用 Cairo 内部插值与缓存。
- `wxGraphicsBitmap` 在多帧绘制过程中可重用，避免反复拷贝像素。

#### 3.3 Linux 典型调用链对比

1. `wxPaintDC` + `DrawBitmap()`：
   - `wxPaintDCImpl` → `wxGTKCairoDCImpl::DoDrawBitmap()` → `wxBitmap::Draw()` → Cairo → GDK → X11/Wayland。

2. `wxGCDC` + `DrawBitmap()`：
   - 与上类似，只是更多操作通过 `wxGraphicsContext` 提供的矢量 API。

3. 直接 `wxGraphicsContext`：
   - `wxGraphicsContext::Create(window)` → `wxCairoContext::DrawBitmap()` → Cairo。

### 4. 高性能图像渲染的一般原则

#### 4.1 避免在绘制路径中重复转换

- 不要在 `OnPaint` 中频繁执行：
  - `wxImage` ←→ `wxBitmap` 转换；
  - `wxBitmap` ←→ `wxGraphicsBitmap` 转换。
- 对于固定资源，应在初始化时完成：
  1. 加载：`wxImage img("xxx.png");`
  2. 一次性缩放到逻辑尺寸：`img.Rescale(w, h, wxIMAGE_QUALITY_HIGH);`
  3. 转换为 `wxBitmap`：`wxBitmap bmp(img, wxBITMAP_SCREEN_DEPTH);`
  4. 再转换为 `wxGraphicsBitmap` 并缓存：
     ```cpp
     wxGraphicsRenderer* renderer = wxGraphicsRenderer::GetDefaultRenderer();
     m_gbmp = renderer->CreateBitmapFromImage(img);
     ```

#### 4.2 优先使用 `wxGraphicsContext` / `wxGCDC`

- 相比纯 `wxDC`：
  - `wxGraphicsContext` 更善于处理 alpha、缩放与旋转。
  - 在 Windows 上可以利用 GDI+ / Direct2D；在 GTK3 上共享 Cairo 上下文。
- 推荐模式：
  - Windows / Linux 通用：
    ```cpp
    void MyPanel::OnPaint(wxPaintEvent&)
    {
        wxAutoBufferedPaintDC dc(this);   // 减少闪烁
        wxGCDC gcdc(dc);                  // 内部持有 wxGraphicsContext
        wxGraphicsContext* gc = gcdc.GetGraphicsContext();

        if (!m_gbmp.IsNull())
        {
            const wxSize sz = GetClientSize();
            gc->DrawBitmap(m_gbmp, 0, 0, sz.x, sz.y);
        }
    }
    ```
- 在 Windows 上，若对性能要求更高，可尝试显式使用 Direct2D 渲染器（见 2.3）。

#### 4.3 针对 alpha / mask 的注意事项

- Windows：
  - 传统 GDI 路径中，带 alpha 的位图和 mask 同时存在会触发额外的合成逻辑（`src/msw/dc.cpp:1171-1181`），存在额外拷贝。
  - GDI+ 路径中，`wxGDIPlusBitmapData` 会将 mask 转为 alpha 并写入 `PixelFormat32bppPARGB`（`src/msw/graphics.cpp:1282-1304, 1384-1407`）。
  - **建议：新代码中优先使用纯 alpha 通道表达透明度，避免同时依赖 mask。**

- GTK/Cairo：
  - `wxBitmap::Draw()` 会选择：
    - 如存在 mask：通过 `cairo_mask()` 应用 mask；
    - 否则依赖 alpha + `cairo_paint()`（`src/gtk/bitmap.cpp:1416-1433`）。
  - 当大量叠加使用 mask 时会多一次 pattern 创建，略微影响性能。

#### 4.4 缩放与插值质量

- 一般策略：
  - UI 图标/线框图：`CAIRO_FILTER_NEAREST` / 低插值质量 → 更锐利，更快。
  - 照片/背景图：使用高质量缩放（先在加载阶段用 `wxImage::Rescale(..., wxIMAGE_QUALITY_HIGH)` 生成目标尺寸位图），绘制阶段不再缩放。

- Windows GDI+ / Direct2D：
  - 可以通过 `wxGraphicsContext` 的插值/抗锯齿设置影响 `DrawBitmap` 的质量与速度（如 `SetAntialiasMode()`、`SetInterpolationQuality()`）。
  - 对滚动、缩放动画，常见做法是：动画阶段降低插值质量，停止时再绘制一帧高质量结果。

#### 4.5 双缓冲与有限重绘

- 双缓冲：
  - 推荐使用 `wxAutoBufferedPaintDC` 或手动 `wxBufferedPaintDC`，避免直接在窗口 DC 上频繁重绘。
  - 对于复杂场景，可使用 `wxMemoryDC` + 后备 `wxBitmap` 做离屏渲染，然后一次性 `Blit()` 到前台。

- 限制重绘区域：
  - 使用 `wxRegion` + `SetClippingRegion()`，在 `OnPaint` 中只重绘 `GetUpdateRegion()` 覆盖的区域。
  - 滚动场景下，使用 `wxWindow::ScrollWindow()` 结合局部重绘，避免整屏重绘。

#### 4.6 平台特定建议小结

- Windows：
  - 简单静态 UI：`wxPaintDC` + `DrawBitmap()`（GDI）已足够。
  - 大量 alpha / 缩放：使用 `wxGCDC` / `wxGraphicsContext`（GDI+），并缓存 `wxGraphicsBitmap`。
  - 高 FPS 动画 / 大图：尝试 Direct2D；必要时考虑 `wxGLCanvas` + OpenGL/Vulkan。

- Linux (GTK3)：
  - 优先使用 `wxAutoBufferedPaintDC` + `wxGCDC`，共享窗口的 Cairo 上下文，避免在每帧创建/销毁 Cairo surface。
  - 将大图预先缩放到接近显示尺寸，避免 Cairo 对超大位图做实时插值。

### 5. 跨平台高性能图像渲染模板

#### 5.1 资源加载与缓存（一次性）

```cpp
class ImageCanvas : public wxPanel
{
public:
    ImageCanvas(wxWindow* parent)
        : wxPanel(parent)
    {
        Bind(wxEVT_PAINT, &ImageCanvas::OnPaint, this);
        LoadImage("my_image.png");
    }

private:
    wxGraphicsBitmap m_gbmp;

    void LoadImage(const wxString& path)
    {
        wxImage img(path);
        if (!img.IsOk())
            return;

        // 例如：预缩放到固定大小
        const int targetW = 800;
        const int targetH = 600;
        img.Rescale(targetW, targetH, wxIMAGE_QUALITY_HIGH);

        wxGraphicsRenderer* renderer = wxGraphicsRenderer::GetDefaultRenderer();
        if (!renderer)
            return;

        m_gbmp = renderer->CreateBitmapFromImage(img);
    }

    void OnPaint(wxPaintEvent&)
    {
        wxAutoBufferedPaintDC dc(this);
        wxGCDC gcdc(dc);
        wxGraphicsContext* gc = gcdc.GetGraphicsContext();

        gc->SetAntialiasMode(wxANTIALIAS_DEFAULT);

        if (!m_gbmp.IsNull())
        {
            const wxSize sz = GetClientSize();
            gc->DrawBitmap(m_gbmp, 0, 0, sz.x, sz.y);
        }
    }
};
```

特点：

- 加载阶段只进行一次 `wxImage` → `wxGraphicsBitmap` 转换。
- 绘制阶段仅调用 `DrawBitmap()`，避免昂贵拷贝。
- 在 Windows / Linux(GTK3) 上都能走各自的高质量渲染路径。

#### 5.2 Windows 下显式选择 Direct2D（可选）

```cpp
wxGraphicsContext* CreateBestGraphicsContext(wxWindow* window)
{
#ifdef __WXMSW__
    if (wxGraphicsRenderer* d2d = wxGraphicsRenderer::GetDirect2DRenderer())
        return d2d->CreateContext(window);
#endif
    return wxGraphicsContext::Create(window);
}
```

使用方式示例：

```cpp
void MyPanel::OnPaint(wxPaintEvent&)
{
    wxPaintDC dc(this);

    std::unique_ptr<wxGraphicsContext> gc(CreateBestGraphicsContext(this));
    if (!gc)
        return;

    if (!m_gbmp.IsNull())
    {
        wxSize sz = GetClientSize();
        gc->DrawBitmap(m_gbmp, 0, 0, sz.x, sz.y);
    }
}
```

这在 Windows 7+ 且启用了 Direct2D 时，会自动走 D2D 路径，否则回退到 GDI+。

### 6. 总结

- **Windows：**
  - 传统 `wxDC` 路径基于 GDI（`wxMSWDCImpl::DoDrawBitmap()`），适用于简单 UI。
  - `wxGraphicsContext` 默认基于 GDI+（`wxGDIPlusContext::DrawBitmap()`），支持高质量缩放与 alpha。
  - Direct2D 后端提供 GPU 加速，适合大量动态图像。

- **Linux(GTK3)：**
  - 所有主要 DC 最终都会通过 `wxGTKCairoDCImpl` 将绘制委托给共享的 Cairo 上下文。
  - `wxBitmap::Draw()` 与 `wxCairoContext::DrawBitmap()` 使用 Cairo pattern + matrix 实现缩放与混合。

- **高性能关键点：**
  - 尽量把 `wxImage`→`wxBitmap`→`wxGraphicsBitmap` 转换移出绘制循环。
  - 选择合适的渲染路径（GDI / GDI+ / D2D / Cairo），并缓存 `wxGraphicsBitmap`。
  - 利用双缓冲与区域重绘减少 overdraw。

在此基础上，针对具体业务（如大图浏览器、时间轴视图、地图/图谱等），可以进一步在上层实现中加入图块缓存、分级缩放（mipmap）、异步加载等策略，以充分发挥 wxWidgets 在不同平台上的图像渲染能力。
